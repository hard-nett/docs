# TanStack Query Hook Codegen — Indexer-Optimized Contract Query Layer

## Problem

Every new contract integration requires hand-writing TanStack Query hooks that:
- Map contract query methods to `useQuery()` hooks
- Implement indexer-first / chain-fallback pattern
- Maintain correct query keys for cache dedup
- Preserve full TypeScript types from the contract client

This is repetitive, error-prone, and blocks rapid integration of new contracts. We have ts-codegen generating typed clients — we should auto-generate the query layer too.

## Architecture

```
  Contract Schema (JSON)
       │
       ▼
  ts-codegen (existing)
       │ generates
       ▼
  QueryClient classes (.client.ts)
  Type definitions (.types.ts)
       │
       ▼
  generate-hooks.ts (NEW)
       │ reads interface + query messages
       ▼
  lib/hooks/use-<contract>.ts (generated)
       │ each hook:
       │   1. try indexer REST path
       │   2. fallback to queryContractSmart
       ▼
  React components consume hooks
```

## Manifest: `scripts/hook-manifest.json`

```json
{
  "outputDir": "lib/hooks/generated",
  "typesDir": "lib/types",
  "contracts": [
    {
      "name": "CwCalendar",
      "slug": "cw-calendar",
      "source": "../../path/to/CwCalendar.client.ts",
      "typesSource": "../../path/to/CwCalendar.types.ts",
      "contractConfigKey": "calendar",
      "indexerBase": "/indexer/cw-calendar",
      "indexerMethods": ["config", "list_events", "list_groups", "upcoming_events"]
    }
  ]
}
```

- `slug` → query key prefix and output filename
- `contractConfigKey` → key in `CONTRACTS` config object
- `indexerBase` → REST path prefix for indexer queries
- `indexerMethods` → which methods have indexer support (rest go direct to chain)

## Script: `scripts/generate-hooks.ts`

**Parsing** — two passes on the `.client.ts` file:

1. Extract `ReadOnlyInterface` methods:
   - Method name, parameter types, return type
   - Regex: `(\w+):\s*\(([^)]*)\)\s*=>\s*Promise<(\w+)>`

2. Extract query message shapes from `QueryClient` class:
   - The exact `{ method_name: { ...params } }` object
   - Regex on `queryContractSmart\(this\.contractAddress,\s*(\{[\s\S]*?\})\s*\)`

**Generation** — for each method, emit:

```ts
export function use{PascalMethod}({params}: {ParamType}) {
  return useQuery({
    queryKey: ['{slug}', '{method_name}', ...paramValues],
    queryFn: () => indexerWithFallback<{ReturnType}>(
      { {method_name}: { ...params } },
      {hasIndexer ? `'${indexerBase}/{method_name}'` : 'undefined'},
    ),
    {needsEnabled ? `enabled: ${enabledCondition},` : ''}
  });
}
```

**Smart behaviors**:
- Methods with params get `enabled: !!requiredParam` guards
- Pagination methods (`limit`, `startAfter`, `startBefore`) get param-based query keys
- Query keys include all params for proper cache dedup
- Types file is copied to `lib/types/` so imports work without external repo deps

## Generated output structure

```
lib/
  types/
    CwCalendar.types.ts        ← copied from ts-codegen output
    CwInfuser.types.ts         ← copied from ts-codegen output
  hooks/
    generated/
      use-cw-calendar.ts       ← auto-generated, DO NOT EDIT
      use-cw-infuser.ts        ← auto-generated, DO NOT EDIT
    use-calendar.ts            ← hand-written (current), migrates to generated
    use-wallet-groups.ts       ← hand-written (stays, calls generated hooks)
```

## Generated file template

```ts
// AUTO-GENERATED by scripts/generate-hooks.ts
// Source: CwCalendar.client.ts
// Do not edit — re-run `pnpm generate-hooks` to update.
'use client';

import { useQuery } from '@tanstack/react-query';
import { queryContractSmart, queryREST } from '@/lib/queries/fetchers';
import { CONTRACTS } from '@/lib/wallet/config';
import type {
  CalendarConfig,
  EventListResponse,
  EventResponse,
  GroupListResponse,
  // ... all response types
} from '@/lib/types/CwCalendar.types';

const KEY = 'cw-calendar';

async function indexerWithFallback<T>(
  queryMsg: Record<string, unknown>,
  indexerPath?: string,
): Promise<T> {
  if (indexerPath) {
    try { return await queryREST<T>(indexerPath); } catch { /* fall through */ }
  }
  return queryContractSmart<T>(CONTRACTS.calendar, queryMsg);
}

export function useConfig() {
  return useQuery({
    queryKey: [KEY, 'config'],
    queryFn: () => indexerWithFallback<CalendarConfig>(
      { config: {} },
      '/indexer/cw-calendar/config',
    ),
  });
}

export function useListEvents(params?: {
  filter?: EventFilter;
  startAfter?: number;
  limit?: number;
}) {
  return useQuery({
    queryKey: [KEY, 'list_events', params?.filter, params?.startAfter, params?.limit],
    queryFn: () => indexerWithFallback<EventListResponse>(
      { list_events: { filter: params?.filter, start_after: params?.startAfter, limit: params?.limit } },
      '/indexer/cw-calendar/list_events',
    ),
  });
}

export function useEvent(params: { eventId: number }) {
  return useQuery({
    queryKey: [KEY, 'event', params.eventId],
    queryFn: () => indexerWithFallback<EventResponse>(
      { event: { event_id: params.eventId } },
    ),
    enabled: params.eventId !== undefined,
  });
}

// ... generated for every query method
```

## `CONTRACTS` config expansion

When a new contract is added via manifest, the script checks `lib/wallet/config.ts` and warns if the `contractConfigKey` isn't present:

```
⚠ Contract key "infuser" not found in CONTRACTS config.
  Add it to lib/wallet/config.ts:
    export const CONTRACTS = {
      calendar: '',
      infuser: '',  // ← add this
    };
```

## Package scripts

```json
{
  "scripts": {
    "generate-hooks": "tsx scripts/generate-hooks.ts",
    "generate-hooks:check": "tsx scripts/generate-hooks.ts --check"
  }
}
```

`--check` mode: verifies generated files are up-to-date without overwriting (for CI).

## Migration path for existing hooks

1. When calendar bundle arrives → add to manifest → run codegen
2. Generated `lib/hooks/generated/use-cw-calendar.ts` replaces hand-written `lib/hooks/use-calendar.ts`
3. `use-wallet-groups.ts` imports from generated hooks instead
4. Hand-written hooks stay for cross-contract composition (e.g., membership checks that combine group + DAO queries)
